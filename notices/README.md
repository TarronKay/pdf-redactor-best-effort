# Prepared third-party notices for the isolated AGPL candidate

Prepared 2026-10-15. The original application license is `../LICENSE` and `../LICENSING.md`. Third-party code/resources keep their own licenses. This directory is prepared evidence for packaging; it does not certify the final binary or accept Microsoft terms.

`notice-provenance.json` pins 225 copied notice files. Every copied file retains its original bytes, source path/URL and, for the pinned MuPDF source, the exact tar member and source SHA-256. MuPDF notices were updated from 1.28.0 to the matching released 1.28.2 source on 2026-10-15. No application code or source archive was changed by notice preparation.

- `mupdf-1.28.2/` contains 92 legal/author files from the official full 1.28.2 tarball, SHA-256 `44075a84e329db55b9bef5f342a70fd26d69e48ad1d33cb89d9664581c641156`. This includes complete AGPL, native-library notices, FreeType alternatives, IJG README, Droid Apache NOTICE, Han/Noto/SIL/URW font licenses, and all 48 per-language hyphenation notices. All 92 legal files and compared resource/build configuration files are byte-identical to the earlier 1.28.0 evidence. The released 1.28.2 wheel records this exact source-release URL; these notices do not establish provenance for the historical 1.29.0 DLL.
- `installed-dependencies/` preserves existing runtime/packaging license texts, including CPython Windows additional conditions. The stale installed PyMuPDF one-line dual-license notice was excluded; full exact-source text is present instead.
- `additional-native-sources/` preserves existing prepared CPython/Pillow/native legal evidence with archive origins. Some upstream files govern tools/tests or alternate features absent from the final binary. They are not all claimed to govern the application. Pillow and MuPDF may bundle different versions of a library; their source notices must not be collapsed into one guessed version.
- `runtime-additions/` includes the complete Pillow composite license, Raqm MIT text, full PyMuPDF AGPL and draft credits. Historical wording refers to the immutable evaluation MSI; the new candidate still needs actual packaging verification.
- `Microsoft/` separates Microsoft component conditions, current official 2026 runtime text, and reference developer terms. These restrictions do not replace AGPL application rights. The unaccepted recipient-terms review checklist is outside this packet in `release_candidate/provenance_followup/`.
- `hyphen-fulltexts/` and `hyphen-additions-provenance.json` add full LGPL/GPL/LPPL texts and pinned Romanian upstream context. Resource mapping is documented in `release_candidate/provenance_followup/HYPHENATION_REVIEW.md`.
